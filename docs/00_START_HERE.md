## Rules

- Do not make code changes until explicitly approved.
- Do not push changes without explicit approval.
- Prefer simple solutions over architectural perfection.
- Preserve existing project direction unless asked to challenge it.
- Explain tradeoffs before implementation.
- Assume prior chat history may be unavailable.
- Use the documentation as the primary source of truth.

---

## Success Criteria
A new engineer, product manager, founder, or AI assistant should be able to understand the project and continue development without access to prior conversations.
